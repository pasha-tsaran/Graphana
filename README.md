# Мониторинг и логирование: Loki + Grafana

Стек для приёма, хранения и просмотра логов. Loki принимает сообщения по HTTP, Grafana показывает их в таблице и на круговой диаграмме. Отдельное тестовое приложение непрерывно эмулирует события криптовалютного сервиса.


## Надо

Для запуска нужны Docker Engine с Docker Compose либо Docker Desktop. На машине должны быть свободны порты `3000` и `3100`. Интернет нужен при первой загрузке образов и сборке приложения.

Для запуска `scripts/verify.py` дополнительно нужен Python 3.12 на машине, где выполняются команды Docker Compose. Сам скрипт проверки использует стандартную библиотеку Python; зависимости приложения устанавливаются внутри контейнера.

Все команды ниже выполняются из корня проекта.

## Запуск

Полный стек с тестовым приложением:

```bash
docker compose -f docker-compose.yml -f compose.app.yaml up -d --build
```

Только Loki и Grafana:

```bash
docker compose up -d
```

Проверка состояния контейнеров:

```bash
docker compose -f docker-compose.yml -f compose.app.yaml ps
```

В полном стеке должны работать `loki`, `grafana` и `test-app`. После старта дождитесь готовности Loki и Grafana: контейнер в состоянии running может ещё проходить инициализацию.

| Сервис | Локальный адрес | Адрес развёрнутого сервера |
| --- | --- | --- |
| Grafana | http://localhost:3000 | http://193.187.96.95:3000 |
| Дашборд | http://localhost:3000/d/my-app-logs | http://193.187.96.95:3000/d/my-app-logs |
| Готовность Loki | http://localhost:3100/ready | http://193.187.96.95:3100/ready |

Стандартные данные входа в Grafana: **admin / admin**. При первом входе Grafana может предложить сменить пароль.

На сервере проект расположен в `/root/Loki+Grafana`.

## Настройки

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `GRAFANA_ADMIN_USER` | `admin` | Начальный логин администратора Grafana |
| `GRAFANA_ADMIN_PASSWORD` | `admin` | Начальный пароль администратора Grafana |
| `LOKI_URL` | `http://localhost:3100` | Базовый адрес Loki для Python-отправщика и скрипта проверки |
| `APP_NAME` | `my_app` | Метка приложения в отправляемых логах |
| `GRAFANA_URL` | `http://localhost:3000` | Адрес Grafana для скрипта проверки |

Для задания начальных учётных данных скопируйте `.env.example` в `.env` и измените значения до первого запуска. Переменные администратора в Compose применяются при создании базы Grafana. Для уже существующей базы смена значения в `.env` не меняет пароль пользователя.

В `compose.app.yaml` для приложения задан `LOKI_URL=http://loki:3100`: внутри Docker сервисы обращаются друг к другу по имени. Для запуска отправщика на хосте используется `http://localhost:3100`.

Дашборд и скрипт проверки настроены на `app="my_app"`. Если меняете `APP_NAME`, соответствующие запросы тоже нужно изменить.

## Источник данных и дашборд

Источник Loki загружается автоматически из `grafana-datasource.yaml`. Проверить подключение вручную можно в Grafana: **Connections → Data sources → Loki → Save & test**.

Дашборд загружается из `grafana/dashboards/my-app-logs.json`.

Запрос таблицы:

```logql
{app="my_app"}
```

Запрос круговой диаграммы:

```logql
sum by (level) (count_over_time({app="my_app"}[$__range]))
```

Для диаграммы используется режим **Instant**: каждый сектор показывает количество сообщений соответствующего уровня за выбранный период. При смене интервала переменная `$__range` обновляется, и распределение пересчитывается.

## Отправка логов из приложения

Функция находится в `app/loki_client.py`:

```python
from loki_client import send_log_to_loki

send_log_to_loki("Приложение запущено", "system", "INFO")
send_log_to_loki("Ошибка тестовой транзакции", "trading", "ERROR")
```

Сигнатура: `send_log_to_loki(message, job="crypto-backend", level="INFO", *, app=None, loki_url=None, timeout=5.0)`.

Доступные уровни: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. Сообщение получает метки `app`, `job`, `level` и `service="crypto-backend"`. Тело запроса содержит `streams`, объект меток `stream` и массив `values` с парой `[timestamp, message]`. Timestamp передаётся строкой в наносекундах. Успешная отправка подтверждается HTTP 204; при сетевой ошибке или другом HTTP-статусе функция вызывает исключение.

Сделки, цены и действия пользователей в тестовом приложении моделируются случайным образом.

## Проверки

### 1. Сформировать тестовые события

После запуска полного стека отправьте 30 сообщений. В набор гарантированно входят уровни `INFO`, `DEBUG`, `WARNING` и `ERROR`:

```bash
docker compose -f docker-compose.yml -f compose.app.yaml exec -T test-app python main.py --once --count 30
```

Ожидаемый результат: строки `Sent [LEVEL] ...` и код завершения `0`. При неудачной доставке хотя бы одного сообщения команда возвращает ненулевой код.

Эта команда не останавливает основной процесс приложения: непрерывная генерация событий продолжается.

### 2. Запустить автоматическую проверку

На Linux/macOS:

```bash
python3 scripts/verify.py
```

В Windows PowerShell:

```powershell
python scripts/verify.py
```

Скрипт нужно запускать рядом с файлами Compose, используя тот же Docker context, в котором работает тестируемый стек. Он отправляет уникальное русское сообщение через функцию внутри `test-app`, затем проверяет:

- ответ Loki `/ready` и состояние базы Grafana;
- настройки и успешное подключение источника Loki;
- наличие двух панелей и автообновления 5 секунд;
- логи четырёх уровней за последние 15 минут;
- доставку уникального сообщения без искажения UTF-8;
- непустые результаты запросов обеих панелей через API Grafana.

Успешный результат: код завершения `0` и `"status": "passed"`. Отчёт записывается в `evidence/verification.json`; при каждом запуске он обновляется.

Если пароль Grafana был изменён, перед проверкой укажите актуальные данные в окружении. Файл `.env` скрипт Python автоматически не читает.

Linux/macOS:

```bash
export GRAFANA_ADMIN_USER=admin
export GRAFANA_ADMIN_PASSWORD='ваш_пароль'
python3 scripts/verify.py
```

Windows PowerShell:

```powershell
$env:GRAFANA_ADMIN_USER = 'admin'
$env:GRAFANA_ADMIN_PASSWORD = 'ваш_пароль'
python scripts/verify.py
```

Для проверки развёрнутого сервера подключитесь к нему, перейдите в `/root/Loki+Grafana` и выполните те же команды. Простого изменения `GRAFANA_URL` недостаточно: отправка контрольного сообщения выполняется через Docker Compose.

### 3. Проверить отображение вручную

1. Откройте дашборд и выберите последние 15 минут.
2. Убедитесь, что в таблице есть новые сообщения и русские символы отображаются корректно.
3. Проверьте наличие секторов диаграммы и значений по уровням.
4. Измените период времени: распределение должно пересчитаться.
5. Подождите несколько обновлений и убедитесь, что новые события появляются автоматически.

## Логи и диагностика

```bash
# Последние сообщения приложения
docker compose -f docker-compose.yml -f compose.app.yaml logs --tail 30 test-app

# Логи Loki и Grafana
docker compose logs --tail 50 loki grafana
```

| Симптом | Что проверить |
| --- | --- |
| Grafana не открывается | Состояние контейнера, доступность порта 3000 и логи Grafana |
| Источник подключён, но нет labels | Запуск `test-app`, успешную доставку событий и адрес `http://loki:3100` внутри контейнера |
| Панели пустые | Метку `app="my_app"`, выбранный период и отправку тестового набора |
| Проверка возвращает HTTP 401 | Актуальные логин и пароль Grafana в окружении скрипта |
| Скрипт не находит `test-app` | Текущий каталог, Docker context и запуск с обоими файлами Compose |
| Сразу после старта проверка не проходит | Готовность сервисов; повторите проверку после завершения инициализации |

## Остановка и данные

Остановить полный стек:

```bash
docker compose -f docker-compose.yml -f compose.app.yaml down
```

Данные остаются в томах `lokigrafana_grafana-data` и `lokigrafana_loki-data`. Для обычной остановки используйте команду без `-v`, чтобы сохранить тома. В Loki настроено хранение логов в течение 168 часов.

Повторный запуск выполняется той же командой `up -d --build` с обоими файлами Compose.
